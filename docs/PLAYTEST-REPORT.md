## 二、各画像试玩记录

### 1. 硬核推理党（诚实计时）——"1024 秒够认真玩，但不够贪心"

完整路径：跳过简报 → 7 个调查全做（238s）→ 9 个 Agent 全问（162s）→ 每人 1 个话题（144s）→ 出示 8 次线索 → 结案。**共用 658s，剩余 366s**。

高光时刻：向 DeepSeek 出示 C-04 → "DeepSeek 的证据链对上了。她不是凶手。"；向豆包出示 C-17 → "豆包承认了。她按下了清空键。"——破绽机制反馈明确，有"审问突破"的爽感。

问题：选了"系统故障"论断得 I。S 结局需要选"误以为练习室"——4 个论断里唯一指向"她不是坏人"的选项，跟"抓真凶"的直觉相反，不看攻略很难想到。

### 2. 纯小白——"白话简报合格，能独立玩到结案"

路径：标题页点"先看 30 秒白话版" → 读完简报（花名册/烧账本/贴错门牌三个比喻覆盖核心机制）→ 直接开始 → 全调查全询问 → 直觉指认 GPT → G 结局。

评价：简报文案质量高，"你不需要懂任何术语。你只需要判断：谁的话对不上，谁在把责任往外推"——精准交代了玩法。游戏中术语表随时可查（8 个词），调查文本自带"（人话：……）"括号注释，全程无理解障碍。最终指认 GPT 是小白最自然的直觉（写错工单还自批自过），G 结局的文案也接住了这个错误："他是源头，仍不是那只手。"

### 3. 速通暴躁老哥——"2 分 14 秒就能通关，时间压力形同虚设"

路径：跳过一切 → 3 个调查拿 7 条线索 → 直接结案指认豆包 → K（B 级）结局，仅用 134s。

这是平衡性的反面：**认真玩家用 658s，速通玩家用 134s，都只能拿一个 B 级**。时间惩罚对速通几乎不存在（除非超时，但 1024s 对速通太充裕）。

### 4. 收集控·真结局线——"S 结局可达，但关键线索不可见"

第一轮尝试：12 条线索 + "误以为练习室"论断 → 只拿 A（差 2 条关键支撑）。原因是随手选的 3 条支撑里只有 1 条权重≥2 的关键线索。第二轮全调查（17 条）+ 定向选关键线索 → **S 达成**。

问题：支撑选择界面只显示线索编号和名称，**不显示哪条是关键证据**。玩家不知道 C-03/04/10/11/14/17 分量更重，S 结局的达成像抽奖。

### 5. 结局抽样 + 超时线——"13 结局体系完整，持久化正常"

C/L/G 三个错指结局文案全部到位（GLM 的"排班表不按清空键——它只是让对的人，在错的时间坐上了控制台"是全游戏最佳台词之一）。J 超时结局："系统自动提交了报告：直接原因——临时工（已离职）。你甚至没来得及看那些秘密一眼。"讽刺到位。localStorage 结局图鉴跨局累积正常（["C","L","G","J"]）。

### 6. 移动端通勤党——"全流程可玩"

390×844 完整走完全调查+全询问+出示+结案。自动模式、声音开关、术语表面板（含"8 个词"正确渲染）均正常。竖屏布局无横向溢出。

### 7. 功能补测——全部正常

作弊面板（9 人真假话）、真相档案（时间线+根因+结局图鉴）、保存结案卡（canvas 生成 PNG 下载）、复制结案文案（clipboard 失败有 toast 兜底）、重新开一夜（location.reload）。

## 三、问题与建议（按优先级）

### P1-1 S 结局的关键线索在支撑界面不可见

- 证据：收集者轮 1，12 线索 + 正确论断，因关键支撑不足 2 条只得 A；定向选关键线索后立刻 S。
- 建议：支撑选择卡片上给权重≥2 的线索加微弱视觉标记（如左下角小红点/星标），或在结案指引里写明"支撑线索的分量会影响评级"。不必说明具体权重数值，给个"这条很重要"的信号即可。

### P1-2 时间预算对两类极端玩家双双失衡

- 证据（诚实计时）：速通 134s 拿 B；全话题党理论成本 27×16 + 238 + 162 = 832s，加上真实阅读时间必超时得 J。
- 建议（任选其一或组合）：
  1. 话题费用 16s → 10~12s（全话题党降到 ~600s，仍有时限感但可完成）；
  2. 总时长 1024s → 1280s；
  3. 或引入"超时前 120s 可选择直接结案不计时"的逃生阀。
- 注意：不要简单超时即死，J 结局的讽刺文案说明作者有意惩罚拖延，但应让"问得多"和"拖时间"区分开。

### P1-3 指认界面没有任何侦查状态信息

- 证据：showAccuse1 的 9 个嫌疑人按钮只有名字+职务，随机排序。玩家进入指认环节时，无法回顾"谁问过、谁有破绽、谁还没碰过"。
- 建议：指认按钮上追加状态徽标——"已询问 ✓"、"破绽 ×N"、"未询问"。信息都在 STATE 里（asked/broken），渲染成本极低，对推理体验提升很大。

### P2-1 超时前的警示不够强

- timer 有 danger 态，但最后 60 秒建议加码：倒计时数字闪烁/变红放大 + 一次提示音 + 对话框出现"即将超时"的系统消息。努力 17 分钟后被自动结案的体验需要预警来兜底。

### P2-2 "重新开一夜"是全页刷新，重开成本高

- 证据：location.reload() → 重看标题页封面轮播 + bootlog 动画（约 8 秒）才能再进游戏。收集结局的玩家每小时要重开十几次。
- 建议：直接重置 STATE 并跳回序章第一幕（保留标题页仅首次进入显示）；或在标题页加"继续新的调查"快捷入口。

### P2-3 真相档案会替换报告面板，返回路径绕

- 证据：从报告点"真相档案"后面板内容被替换，报告的"保存结案卡/复制文案/重新开一夜"全部消失，必须先点 × 关闭档案才回得去（openTruth 有 pClose，路径存在但不顺）。
- 建议：真相档案改为报告页内的展开区块（锚点滚动），或在档案面板底部加"← 返回结案报告"。

### P2-4 复制结案文案的兜底可以更彻底

- clipboard 失败时当前 toast"复制失败，请手动选择"——但文案已经不可见（在剪贴板失败的路径上玩家要去哪儿手动复制？）。
- 建议：失败时把完整文案展开成一个可选中文本框。

### P3-1 小 polished 项（可选）

- 序章 autoNext 2.4s 自动推进对速通友好，但读得慢的玩家会被推着走；建议 autoNext 仅在玩家已有一次点击行为后启用。
- hub 的调查/询问顺序每局随机（shuffle）——重玩性好，保留。
- 破遗成立的立绘 shake + 音效反馈好，保留。

## 四、总体结论

**内容质量：优秀。** 白话化改造彻底（简报+术语表+人话注释三层护航），破绽机制有爽感，13 结局文案全部在线，真相档案是强力收官。硬核、小白、速通、收集、移动端五类用户都能独立完成对局，0 JS 错误。

**主要短板在平衡与信息层，不在内容：**
1. S 结局缺"关键线索"信号（P1-1）
2. 时间预算对速通太松、对全话题党太紧（P1-2）
3. 指认环节缺侦查状态回顾（P1-3）

这三项都是低成本高收益的改动（状态数据都已存在，主要是渲染与数值），建议优先处理。
