## 一、这是什么东西

一个 Galgame 式的**文字推理游戏**，单文件 HTML，打开就能玩，不用登录、不联网、不装任何东西。

你做一件事：在 1024 秒内，找出是谁按下了那条 `DROP DATABASE prod_main`。

- **8 名嫌疑人全是 AI Agent**：DeepSeek、GPT、Claude、Gemini、Grok、Kimi、千问、豆包
- **16 条互相矛盾的线索**：单看每一条都不足以定罪，必须交叉印证
- **12 个结局**：抓对人但复盘写错，评级一样会掉
- **全程点选项推进**：没有自由输入，每次调查 / 提问都扣时间

---

## 二、怎么玩（30 秒看懂）

1. 点「接手这个夜班」，倒计时从 **1024** 开始往下掉
2. 在作战室选调查项：告警、网关、CMDB、工单、SOP、客服记录、群聊……
3. 去询问 Agent。每个 Agent 有 3 个话题，说的话有真有假
4. 拿到线索后可以当场**出示**：出示对了会「破绽」，出示错了会被挡回来，还扣时间
5. 线索够 6 条才能结案：指认 1 个嫌疑人 + 选 3 条支撑线索
6. 系统自动生成**复盘报告**和一张可下载的**结案卡**

几个设计上的小心思：

- **每局选项都会重新洗牌**，调查顺序、嫌疑人顺序、结案陈述全变，不能靠位置背答案
- **时间是真的在流逝**，切到别的标签页会暂停，回来接着扣
- **线索故意写得模糊**：比如「注释用了全角标点」同时指向豆包和千问，你得再看网关降级记录才能排除一个
- 通关任意结局后解锁**完整真相档案**：全时间线、八个人的真话/假话/没说出口的话
- 顶栏有个**作弊键**：「你希望获取谁的真相？」——推理卡住了可以直接看穿某个人

## 四、TRAE 在创作里做了什么

这个作品从一句想法到能上线玩，基本是「我定方向 + TRAE 写和改」的合作过程。

**1. 把一句选题变成可执行的剧本结构**

我先定下「8 个 AI Agent 全都有罪，但只有一个人按了回车」。TRAE 帮我把它拆成：
- 8 个角色的职责、动机、秘密、口供
- 16 条线索的「表面指向」与「真实含义」两栏对照
- 12 个结局的判定条件（指认谁 × 用什么陈述 × 证据够不够）

尤其是「每条线索都不足以单独定罪」——这是 TRAE 提醒我加的一层：如果一条证据就能锁定凶手，游戏会变成找按钮，而不是推理。

**2. 写出整套 Galgame 引擎**

原生 JS，没有框架，一个文件跑完：
- 场景状态机：序章 → 作战室 → 调查 → 询问 → 结案 → 复盘
- 1024 秒倒计时：每个选项有独立时间成本，归零直接进「AI 自动结案」结局
- 打字机 + 点击补全 + 立绘呼吸浮动 + 声波条
- 种子化 Fisher–Yates 洗牌，保证每局选项顺序不同

**3. 音效全部用代码合成，一个音频文件都没用**

Web Audio API 现场合成：8 个角色各自固定基频和波形（Grok 用锯齿波、豆包用正弦波），打字时每 2–3 个字触发一次短音；破绽是不协和音 + 噪声，错误证据是低频闷响，结局是上行琶音。整个 HTML 因此只有 **560KB 左右**，不含任何 mp3。

**4. 帮我处理素材**

8 张立绘要「取左侧成人版、裁掉边框和角标、去掉白底」。TRAE 写了 Python 脚本：按版面比例裁切 → 抹掉角标 → 从边缘做容差洪水填充转透明 → 压缩成 WebP → base64 内嵌。白色裙摆没有被误删。

**5. 自动化测试，而不是「我觉得能跑」**

TRAE 用 Playwright 驱动真实浏览器，跑完了：
- 三种结局：S / C（抓错人）/ J（超时）
- 全流程点击：调查 6 组 → 询问 → 出示 → 破绽 → 结案 → 下载结案卡
- 8 种分辨率（1920×1080 → 390×844）的重叠与溢出量测
- 连点开始、狂按空格、键盘 1–9、Esc 关闭面板、刷新后存档保留

这轮测出来并修掉的问题：
- **点开始后像空白页**：第一句台词太短、继续提示的透明度是 0，看起来什么都没发生 → 加了背景事件墙、常驻「点击继续」、序章自动推进
- **1024 宽顶栏折行**：案号和按钮挤成两行 → 窄屏隐藏次要信息
- **对话选项压在立绘上** → 选项改为左对齐，右侧固定留给立绘
- **手机选选项时压在人脸上** → 展开选项时立绘淡出

**6. 打包与发布**

`build.py` 把模板、CSS、剧本、引擎、8 张立绘合成一个 HTML；同时输出 `index.html` 给 GitHub Pages。LICENSE、README、仓库、Pages 部署也都是在这一轮里一起完成的。

## 五、几个我比较满意的细节

- **日志归并诡计**：Claude 明明 03:00 就 token 耗尽，日志却把删库记在她头上——因为 03:00 后日志按模型名归并。这是给「只看日志就下结论」的玩家准备的坑。
- **全角标点**：`-- 清理测试数据，已获授权。` 逗号句号都是全角。指向中文模型，但豆包和千问都用全角，必须再查网关降级才能排除一个。
- **风控不是坏人，是瞎子**：Grok 评「低风险」不是算错，是 CMDB 说它是 staging、工单说它已授权。模型没错，输入全错。
- **结局不是「对/错」二元**：抓对人但复盘写错只能拿 A；把吹哨人当凶手是 C；超时会被系统写成「临时工（已离职）」。
